# Проверка примера

Текущая версия собрана с Flutter 3.44.1 / Dart 3.12.1; минимальные ограничения
зафиксированы в pubspec.yaml.

1. Нажмите «Записать с клавиатуры», нажмите и отпустите сочетание, затем
   «Добавить сочетание». Для F13–F24 также доступен список.
2. Удерживайте клавишу 2–3 секунды. Индикатор должен стать активным, а журнал
   показать ровно один PRESS. Отпустите: один RELEASE.
3. Сверните окно. Повторите. Разверните окно и проверьте журнал.
4. Назначьте Ctrl+Alt+Shift+Space. Отпустите Space первым, затем повторите и
   отпустите Ctrl первым. В обоих случаях действие должно завершиться.
5. Во время удержания нажмите «Пауза»: немедленный RELEASE. Возобновите,
   продолжая удерживать клавишу: нового PRESS нет до отпускания и нового нажатия.
6. Начните запись другого сочетания: старые хоткеи временно не вызывают действия.
   Отмените настройку: предыдущий режим восстанавливается.
7. Попробуйте добавить дубликат: появится ошибка, исходное назначение сохраняется.
8. Добавьте два разных сочетания и удерживайте их одновременно. Удалите активное
   назначение: оно получает RELEASE, другое продолжает работать.

Пример не управляет микрофоном; счётчики проверяют реальные callback-функции.
Назначения сбрасываются после закрытия приложения.

## Команды на этой Windows-машине

Из корня репозитория:

```powershell
$env:DART_SUPPRESS_ANALYTICS='true'
$taskDart = 'C:\Users\vio\Documents\flutter\bin\cache\dart-sdk\bin\dart.exe'
$taskFlutter = 'C:\Users\vio\Documents\flutter\bin\cache\flutter_tools.snapshot'
& $taskDart pub get
& $taskDart run build_runner build
& $taskDart analyze
& $taskDart $taskFlutter test
Set-Location example
& $taskDart $taskFlutter run -d windows
```

Генерируемые `.g.dart` / `.freezed.dart` включены в исходники: потребителю пакета
не нужно запускать генерацию. После изменения аннотаций запускайте build_runner.
Для генерации example отдельно используйте `dart.exe run build_runner build`
из `example`; из корня генератор также видит example.

Автотесты проверяют реальную логику Riverpod-контроллера с тестовым транспортом:
автоповтор, модификаторы, паузу, одновременные действия, дубликаты, ошибки
регистрации, очистку и portal-события. Они не заменяют аппаратную проверку
на Windows/Linux/macOS и проверку системного диалога Wayland.

## До публикации

Публикация сейчас заблокирована `publish_to: none`. Перед релизом нужны проверка
Linux/macOS на реальных устройствах, тесты portal-разрешений и выбора сочетания,
проверка лицензии/авторства, адрес публичного репозитория и доступность имени
на pub.dev. Список известных платформенных ограничений — в PLATFORMS.md.
